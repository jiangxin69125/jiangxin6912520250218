# Project Decisions

This file records project decisions that affect security, maintainability, or future automation.

## 2026-06-19

### Use maintained CSRF middleware

Decision: Use `csrf-csrf` instead of `csurf`.

Reason: `csurf` is archived and no longer maintained. `csrf-csrf` implements a stateless double-submit cookie pattern and currently audits cleanly in this project.

### Keep generated dependencies out of Git

Decision: Commit `package-lock.json`, but ignore `node_modules/`.

Reason: `package-lock.json` captures dependency resolution. `node_modules/` is generated by `npm install` and should not be versioned.

### Add machine-readable health and project checks

Decision: Provide `/health` and `npm run doctor -- --json`.

Reason: Local automation and agent workflows need small, deterministic checks that can be parsed without reading logs meant for humans.

### Centralize outbound HTTP calls

Decision: Route future outbound JSON HTTP calls through `lib/httpClient.js`.

Reason: Network calls should have a timeout, host allowlist, local/private host blocking, bounded error bodies, and consistent error handling instead of ad hoc `fetch` calls in route handlers.

### Scope dependency audit to production dependencies

Decision: Run `npm audit --omit=dev` through `scripts/audit.js` in the project check script.

Reason: The application currently has no development dependencies. Auditing production dependencies keeps the network call smaller and avoids extra npm work while preserving the relevant deployment security check. The wrapper calls `npm.cmd` on Windows to avoid shell resolution problems with PowerShell execution policies.

### Install only stable Matt Pocock skills

Decision: Add the stable engineering and productivity skills from `mattpocock/skills` to `.codex/skills`.

Reason: These skills complement the existing Ponytail workflow without replacing it. Deprecated, in-progress, personal, Claude-specific, and narrow migration/setup helpers are excluded to keep the repo skill set small.
